# Phase 5 "Widen" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** widen the walking skeleton from one free-form question (B02) to the benchmark set. Follow-ups patch the
stored answer spec and redraw the same `Q<n> Answer` in one block (B03, B04, B08). Five recipes produce draft answer
specs v1 (P&L, actual vs plan, monthly trend, cost base, concepts). The full check renders the findings table on the
sheet and adds recon checks per recipe. bench.py route `core` runs B01–B09 and B12–B15 with oracle matching.

**Architecture:** the answer spec v1 (`core/contract.py`) stays the only contract, and no tool is added (the tool
count stays 35).

- `sv_answer` gains three things:
  - `followup` (a patch, applied with `contract.patched` to the spec stored in `_svmeta`);
  - `q` (which answer to patch; default: the current one);
  - a `recipe` field in the spec: `{name, params, overrides}`, which the server expands into `pulls` + `layout`
    before validation.
- New core modules:
  - `core/followup.py`: pure source planning: reuse / refetch / drop per pull id;
  - `core/owned.py`: the tool-owned range of an answer sheet;
  - `core/findings.py`: the findings table on the sheet;
  - `core/recipes/`: one module per recipe and a registry.
- Recipes reuse `templates.py` (pull definitions, and the `answer()` builders run on stub pulls), `fin_spec.py`
  (unchanged) and `concepts.plan` (unchanged logic, English strings).
- The data-dependent parts move into the spec grammar, so they are evaluated after the pull:
  - key points become `auto_points`;
  - the cost-base ranking becomes a `repeat.over.top` in `specs.expand`;
  - the P&L warehouse reconciliation becomes `layout.expect`.

**Tech Stack:** Python 3.12, pydantic v2, pywin32 COM (Excel), pytest + anyio, ruff, uv. The live bench needs EPM
and Excel.

## Decisions taken in this plan (owner may override)

| # | Decision | Why |
|---|---|---|
| D1 | **Follow-up = `sv_answer(followup={...}, q=None)`**; `spec` and `followup` are mutually exclusive. `q` defaults to the current answer: the active sheet if it is `Q<n> Answer`, otherwise the highest `q` with a stored v1 spec. A new question is always `sv_answer(spec=...)` and gets a new `Q<n>`. | One tool; the agent sends only the change. Follow-up vs new is the agent's call, and the rule is in the docstring and SKILL.md: "follow-up edits the current answer unless the user says new question". |
| D2 | **Patch semantics** (`contract.patched`): <br>• dicts merge (`specs.merge`) and `None` deletes; <br>• `pulls` merge by `id`; <br>• `layout.sections` merge by `title`, and inside a section `lines` merge by `key`; <br>• `layout.checks` merge by `label`; <br>• `{"<id-field>": x, "drop": true}` removes an item; unmatched items are appended; <br>• any other list replaces, unless the patch value is `{"append": [...]}` (used by `notes`, `key_points`, `assumptions`, `commentary.drivers`). | B03 adds a line to one section without restating the layout. B04 *adds* a note (a plain list would replace the notes). B08 appends a section. Sections have no key in the grammar, but titles are unique in practice; the patch fails validation if two sections share a matched title. |
| D3 | **Source reuse:** <br>• a pull whose normalised definition (`contract.Pull.model_dump()`) is unchanged keeps its sheet, read back with `userexcel.load_pulls`, with no re-fetch; <br>• a changed pull: its old sheet is parked (`~name`), the pull is fetched fresh under the clean name, and the parked sheet is dropped on success or restored on failure; <br>• a removed pull: its sheet is deleted after success; <br>• `layout.expect` cells of a changed pull are dropped. | "No re-fetch for unchanged pulls"; formulas referencing a parked sheet follow it back on restore. |
| D4 | **Tool-owned range:** `A1:<last col><last row>` of what the tool drew (table + checks + notes + findings) is saved with the spec (`owned: {rows, cols}`). <br>• A redraw clears only that block and deletes only charts named `smartass chart*`. <br>• Before writing a taller or wider answer, rows or columns are inserted if the growth band holds user content. <br>• `styling.apply_report` gets `roles["last_row"]` so it never re-styles below the owned block. | The user's own cells, formats and charts outside the block survive (requirement). Answers drawn before phase 5 have no `owned`, so they are fully cleared as today. |
| D5 | **Follow-up safety:** the answer sheet is copied (`~Q<n> Answer`, hidden) before the redraw. If the redraw fails, the copy replaces the broken sheet; on success the copy is deleted. During a follow-up the status shows in Excel's status bar only; the skeleton (`progress.show`) is not redrawn. | Pulls and prepare run before anything is cleared, but `answer.build` can still fail half-way. `progress.show` would clear the user's sheet. |
| D6 | **Recipes are invoked through the spec**: `{"recipe": {"name": "monthly_trend", "params": {...}, "overrides": {<patch>}}}` with no `pulls`/`layout`. <br>• `sv_answer` expands it server-side: draft, then `contract.patched(draft, overrides)`, then validate. <br>• The stored spec is the expanded spec plus the `recipe` field (provenance). <br>• `sv_answer` returns an `outline` (pull ids, section titles, line keys, column headers, check labels), so follow-ups can be written without the full draft. <br>• Rejected alternative: a `sv_recipe` tool that returns the draft for the agent to edit. It adds a tool and puts 5–60 KB of draft spec (P&L) into the agent's context, which the agent then has to echo back unchanged. | The tool surface stays small, the spec stays the contract (one validation path), and the agent sends a few hundred bytes. `overrides` and later follow-ups are ordinary patches. |
| D7 | **Recipes are pure given a `RecipeContext`** (closed month, catalog, member-label function, P&L-facts function, `now`). The tool job builds the context (`templates.closed_month(h)`, `tools_fin.prepare`). Recipes never touch Excel or HTTP. Tests inject fakes. | Testable without EPM; the closed month comes in from outside, so `Oct 26` now and `Nov 26` next month work without code changes. |
| D8 | **Reuse, not rewrite:** <br>• `actual_vs_plan` and `monthly_trend` call the `templates` function for its `Plan.pulls`, and its `answer()` on *stub pulls* (`sheet` = pull id, no values) for the layout; value-based key points are dropped and `auto_points` drafts them after the pull. <br>• `cost_base` uses the template's pull plus a new `templates.cost_base_members` (extracted, not rewritten); its ranking needs data, so it becomes the grammar's `repeat.over.top`. <br>• `pnl` wraps `fin_spec.build` unchanged. <br>• `concept` wraps `concepts.plan` (its fixed strings are translated to English). | The task says reuse. The template `answer()` functions only read values for key points and labels, and stubs make those inert. |
| D9 | **P&L warehouse recon** travels in the spec as `layout.expect = {"source": "Warehouse"|"Live read", "cells": {pull id: [[row, col, value, fact id, tol], ...]}}`. After the pulls, the pipeline turns it into static checks with `fin_spec.reconcile_pull`, so it is not stored twice. `Check` gains `static`/`detail` (with `expr` optional; exactly one of the two). | `fin_spec` already emits static checks (`Period is closed`, `Unexplained (line bridge)`), and the contract rejected them (expr required). The expectation is data the recipe has before the pull. |
| D10 | **Findings table on the sheet**: after `answer.build` and `check.review`, `core/findings.render` writes a "Findings" block (severity, text; at most 15 lines plus "and N more") below the notes, inside the owned range.     _IDS = {"pulls": "id", "sections": "title", "lines": "key", "checks": "label"}

    def _merge_list(old: list, new, ident: str | None, where: str) -> list:
        if isinstance(new, dict) and set(new) == {"append"}:
            return list(old) + copy.deepcopy(list(new["append"]))
        if ident is None or not isinstance(new, list):
            return copy.deepcopy(new)
        out = copy.deepcopy(list(old))
        for item in new:
            k = item.get(ident)
            hits = [i for i, x in enumerate(out) if x.get(ident) == k]
            if len(hits) > 1:
                raise ValueError(f"{where}: {ident} '{k}' is used twice; the patch cannot tell which one")
            if item.get("drop"):
                if hits:
                    out.pop(hits[0])
                continue
            if hits:
                out[hits[0]] = _merge(out[hits[0]], item, where)
            else:
                out.append(copy.deepcopy(item))
        return out

    def _merge(base: dict, fu: dict, where: str = "spec") -> dict:
        out = copy.deepcopy(base)
        for k, v in fu.items():
            if v is None:
                out.pop(k, None)
            elif isinstance(out.get(k), list) or (isinstance(v, dict) and set(v) == {"append"}):
                out[k] = _merge_list(out.get(k) or [], v, _IDS.get(k), f"{where}.{k}")
            elif isinstance(v, dict) and isinstance(out.get(k), dict):
                out[k] = _merge(out[k], v, f"{where}.{k}")
            else:
                out[k] = copy.deepcopy(v)
        return out

    def patched(spec: dict, follow_up: dict) -> dict:
        """The follow-up applied to a stored spec (raw dict, validated). Dicts merge, None deletes; pulls merge by id,
        layout.sections by title, lines by key, layout.checks by label ({..., "drop": true} removes; unmatched items
        are appended); {"append": [...]} appends to any list; any other list replaces."""
        if (follow_up.get("recipe") or {}).get("params") is not None:
            raise ValueError("recipe parameters cannot be patched: ask it as a new question, or patch pulls/layout")
        out = _merge(spec, follow_up)
        validate(out)
        return out

    def patch(spec: dict, follow_up: dict) -> AnswerSpec:
        return validate(patched(spec, follow_up))
    ```

def growth(old: dict | None, new: dict, used) -> dict:
    """Rows/columns to insert before writing `new` over `old` (both {"rows", "cols"}); used(r1, c1, r2, c2) -> bool
    says whether that band holds anything. No old range (first draw / pre-phase-5 answer): nothing to insert."""
    out = {"rows": None, "cols": None}
    if not old:
        return out
    if new["rows"] > old["rows"] and used(old["rows"] + 1, 1, new["rows"], max(old["cols"], new["cols"])):
        out["rows"] = (old["rows"] + 1, new["rows"])
    if new["cols"] > old["cols"] and used(1, old["cols"] + 1, max(old["rows"], new["rows"]), new["cols"]):
        out["cols"] = (old["cols"] + 1, new["cols"])
    return out


def make_room(ws, old: dict | None, new: dict, com=_com) -> dict:

"""Follow-ups (design §3.3): which answer a follow-up patches and which source sheets it can keep. A pull whose
definition did not change keeps its sheet (no re-fetch); a changed one is fetched again under the same name; a removed
one's sheet is deleted after the redraw succeeded."""
from __future__ import annotations

import re
from dataclasses import dataclass, field

from .. import userexcel
from . import contract

_ANSWER = re.compile(r"^Q(\d+) Answer$")


@dataclass
class SourcePlan:
    reuse: dict[str, str] = field(default_factory=dict)      # pull id -> existing sheet
    fetch: list[str] = field(default_factory=list)           # pull ids to pull, in spec order
    replace: dict[str, str] = field(default_factory=dict)    # changed pull id -> its old sheet (parked, then dropped)
    drop: list[str] = field(default_factory=list)            # sheets of removed pulls


def _norm(p: dict) -> dict:
    return contract.Pull.model_validate(p).model_dump()


def plan_sources(old: dict, old_ids: dict[str, str], new: dict, exists) -> SourcePlan:
    before = {p["id"]: _norm(p) for p in old.get("pulls") or []}
    plan = SourcePlan()
    for p in new.get("pulls") or []:
        pid, sheet = p["id"], old_ids.get(p["id"])
        if sheet and before.get(pid) == _norm(p) and exists(sheet):
            plan.reuse[pid] = sheet
            continue
        plan.fetch.append(pid)
        if sheet and pid in before and exists(sheet):
            plan.replace[pid] = sheet
    kept = {p["id"] for p in new.get("pulls") or []}
    plan.drop = [s for pid, s in old_ids.items() if pid not in kept and exists(s)]
    return plan


def drop_stale_expect(layout: dict, changed: list[str]) -> dict:
    exp = layout.get("expect")
    if not exp:
        return layout
    cells = {k: v for k, v in (exp.get("cells") or {}).items() if k not in changed}
    out = {k: v for k, v in layout.items() if k != "expect"}
    return {**out, "expect": {**exp, "cells": cells}} if cells else out


def _active_sheet(t) -> str:
    return str(userexcel.com(lambda: t.wb.Application.ActiveSheet.Name))


def current_question(t) -> int | None:
    """The answer a follow-up edits: the active Q<n> Answer sheet if it has a stored v1 spec, else the latest one."""
    stored = userexcel.stored_questions(t)
    m = _ANSWER.match(_active_sheet(t))
    if m and int(m.group(1)) in stored:
        return int(m.group(1))
    return stored[-1] if stored else None

"""The review on the sheet (design §3.4): the Critical/Warning/Info findings of check.review as a small block below
the answer's notes, inside the tool-owned range. Written after the build because it needs the calculated checks."""
from __future__ import annotations

from ..userexcel import com as _com

LIMIT = 15
RESERVE = LIMIT + 3          # header + rows + tail + a blank row: room made before the answer is written
_STYLE = {"section": "TN Seksjon", "critical": "TN Note", "note": "TN Note"}
RED = 0x0000C0               # BGR for Excel: dark red


def rows(fs: list[dict], limit: int = LIMIT) -> list[tuple[str, str]]:
    out = [("Findings", "section")]
    if not fs:
        return out + [("No findings: all checks OK.", "note")]
    for f in fs[:limit]:
        out.append((f"{f['severity']} — {f['text']}", "critical" if f["severity"] == "Critical" else "note"))
    if len(fs) > limit:
        out.append((f"… and {len(fs) - limit} more (see the tool result)", "note"))
    return out


def render(ws, row: int, fs: list[dict], col: int = 2, com=_com) -> int:
    """Write the block from `row` in column B; returns its last row."""
    rs = rows(fs)
    last = row + len(rs) - 1
    com(lambda: setattr(ws.Range(ws.Cells(row, col), ws.Cells(last, col)), "Value", tuple((t,) for t, _ in rs)))
    for i, (_, kind) in enumerate(rs):
        c = ws.Cells(row + i, col)
        com(lambda c=c, k=kind: setattr(c, "Style", _STYLE[k]))
        if kind == "critical":
            com(lambda c=c: setattr(c.Font, "Color", RED))
    return last
```

from dataclasses import dataclass, field

from typing import Callable

class RecipeContext:
    closed: str                                  # FinMax Current Reporting Month, e.g. 'Oct 26'
    cat: object                                  # catalog.Catalog

    pnl_facts: Callable | None = None            # (area, period, compare) -> (res, mode, fills, notes, entity)

@dataclass
class Draft:

    layout: dict
    assumptions: list[str] = field(default_factory=list)
    warnings: list[str] = field(default_factory=list)

def pull_dict(ps) -> dict:
    """templates.PullSpec -> contract pull dict (no title: source.sheet_title names it Q<n> <connection> <id>)."""
    ax = lambda a: {"dimension": a.dimension, "members": list(a.members)}
    return {"id": ps.id, "connection": ps.connection, "rows": [ax(a) for a in ps.rows],
            "columns": [ax(a) for a in ps.cols], **({"pov": dict(ps.pov)} if ps.pov else {})}

    """Stand-ins for a template's answer(P) before the pull: sheet = the pull id, no labels, no values (so pull
    cells come out in pull-id form and value-based key points as 'n/a', which the recipe drops)."""
    return {i: SimpleNamespace(sheet=i, row_labels={}, col_labels={},
                               layout=SimpleNamespace(col_tuples=[], nr=0), parsed=SimpleNamespace(rows=[]))
            for i in ids}

    """Template labels fall back to member codes on stubs ('ac.C30', 'ac.C30 — Accumulated Oct 26'): replace the
    leading code with its atlas label, keep the rest."""
    for ln in lines:
        code, _, rest = (ln.get("label") or "").partition(" ")
        if code.startswith(("ac.", "un.", "pr.")):
            ln["label"] = ctx.label(connection, code) + (f" {rest}" if rest else "")

    return {"pnl": pnl.pnl, "actual_vs_plan": plan.actual_vs_plan, "monthly_trend": trend.monthly_trend,

def expand(raw: dict, ctx: RecipeContext) -> tuple[dict, dict]:
    """A spec with a recipe and no layout -> (the full spec, extra tool-result keys). Anything else unchanged."""
    rec = raw.get("recipe")
    if not rec or raw.get("layout"):
        return raw, {}
    if "pnl" not in RECIPES:                     # lazy: the recipe modules import templates/fin_spec (atlas)
        RECIPES.update(_registry())
    fn = RECIPES.get(rec.get("name"))
    if fn is None:
        raise ValueError(f"unknown recipe '{rec.get('name')}'; known: {', '.join(sorted(RECIPES))}")
    d = fn(dict(rec.get("params") or {}), ctx)
    out = {**copy.deepcopy(raw), "pulls": d.pulls, "layout": d.layout,
           "assumptions": list(raw.get("assumptions") or []) + [a for a in d.assumptions
                                                                 if a not in (raw.get("assumptions") or [])]}
    if rec.get("overrides"):
        out = contract.patched({k: v for k, v in out.items() if k != "recipe"}, rec["overrides"]) | {"recipe": rec}
    return out, {**d.result, "warnings": list(d.warnings)}

    """{"top": N, "pull": id, "by": [col members], "among": [row members] (default: every row), "abs": true}
    -> [{"m": member, "label": readable label}] for the N largest, ranked on the pulled values."""
    from .templates import _clean                    # lazy: templates imports the atlas
    p = pulls.get(sheets.get(o["pull"], o["pull"]))
    if p is None:
        return []
    among = o.get("among") or [k[0] for k in p.row_labels]
    vals = [(_pull_value(p, [m], o["by"]), m) for m in among]
    key = (lambda v: abs(v)) if o.get("abs", True) else (lambda v: v)
    ranked = sorted(((key(v), m) for v, m in vals if isinstance(v, (int, float))), reverse=True)[:int(o["top"])]
    return [{"m": m, "label": _clean((p.row_labels.get((m,)) or (m,))[-1]) or m} for _, m in ranked]
